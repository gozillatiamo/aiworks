# Image generation (graphic-designer asset pipeline)

The single reference for how the **graphic-designer** (`Fiona`) generates visual
assets — mascots, icons, logos, decorators, banners — during the design / PRD
pipeline, and how to turn that capability on in a freshly `aiworks sync`'d
workspace. If this is not set up, the design phase must **fail loud**, never
silently ship placeholder art marked dev-ready.

## Config: the `image_generation:` block (default OFF)

The capability is governed by `workspace.config.yaml`:

```yaml
image_generation:
  enabled: false          # MASTER switch (default OFF). false → no images are generated.
  quality: balanced       # fast | balanced | quality — passed to each generate_image call.
  max_per_request: 2      # budget cap: most generations the graphic-designer fires per request.
```

- **`enabled: false` (default)** → the graphic-designer generates nothing (returns every
  asset `unavailable`), and `aiworks sync` does **not** wire up the `mcp-image` server. The
  design phase stays specs/placeholder-only. Turn it on with `enabled: true`.
- **`quality`** is applied per call (the `generate_image` tool's `quality` param), so it
  doesn't depend on the server's env default. **`max_per_request`** is the graphic-designer's
  hard per-request cap.

`scripts/aiworks config` mirrors these into `prd.js` (`IMAGE_GEN_ENABLED` /
`IMAGE_GEN_QUALITY` / `IMAGE_GEN_MAX_PER_REQUEST`); `scripts/aiworks sync` surfaces the state
and only enables `mcp-image` when `enabled: true`.

## The backend: `mcp-image`

Assets are generated by the **`mcp-image`** MCP server (npm package, run via
`npx -y mcp-image`), which exposes `mcp__mcp-image__generate_image` (Gemini —
"Nano Banana"). The graphic-designer drives it through the **`/image-generation`**
skill (`.claude/skills/image-generation/`), which structures prompts as
Subject–Context–Style.

- **Server declaration** — committed in `.mcp.json` (`mcp-image`, stdio via
  `scripts/mcp/mcp-image.sh`), enabled in `.claude/settings.local.json`
  `enabledMcpjsonServers`.
- **Required secret** — `GEMINI_API_KEY` (get one at
  <https://aistudio.google.com/apikey>). The launcher loads it from the
  workspace-root `.env` (direnv) — the single source of truth for MCP secrets.
- **Output** — `IMAGE_OUTPUT_DIR` (defaults to `/tmp/aiworks-generated-images`);
  generated files are uploaded into the product's Figma **Assets page**, so the
  local dir is just scratch staging.
- **Quality** — set per call from `image_generation.quality` (presets: `fast` /
  `balanced` / `quality`; the server env `IMAGE_QUALITY=balanced` is just the fallback).
  Budget rules for the team: configured `quality` + `1K`, **≤ `image_generation.max_per_request`
  generations per request** (default 2).

## Setup (one-time, per machine)

Put MCP secrets in the git-ignored workspace-root **`.env`** (loaded by the
committed `.envrc` → `dotenv` / [direnv](https://direnv.net)). Do **not** put
tokens in `.claude/settings.local.json` — that file only enables MCP servers /
prefs. Cursor does not inject `settings.local` `env` into MCP children; the
stdio wrappers under `scripts/mcp/` read `.env` themselves.

1. Set `image_generation.enabled: true` in `workspace.config.yaml`, then `aiworks sync`
   enables `mcp-image` in `.claude/settings.local.json` and checks that `.env`
   already has `GEMINI_API_KEY` (presence only; never prints the value).
2. Add the key to `.env` if missing:
   ```bash
   printf 'GEMINI_API_KEY=\n' >> .env   # then paste the value; direnv allow if needed
   ```
3. Restart the Claude Code / Cursor session so `mcp-image` starts with the key.

### Verify
```bash
claude mcp list        # mcp-image → ✔ Connected
grep -q '^GEMINI_API_KEY=.\+' .env && echo GEMINI_API_KEY=set
```
A connected server with **no key** still cannot generate — confirm the key is set
in `.env` (exit code only; never `cat` / `grep` the value).

## How the pipeline fails loud (no silent placeholders)

| Layer | Behavior |
|---|---|
| `/prd-design` preflight (step 0b) | **Checks `image_generation.enabled` first** — if off (default), image-gen is UNAVAILABLE by config and the run goes placeholder/specs-only. If on, detects whether `mcp-image` is connected **and** `GEMINI_API_KEY` is set; if not, warns the user and offers: **(a)** enable it, **(b)** proceed placeholder/specs-only with an explicit note, **(c)** abort. Never defaults into (b) silently. |
| graphic-designer | Availability gate first. If the tool is absent or a call errors on auth/key/quota, returns every asset as **`unavailable`** with a reason + fix — never improvises a placeholder it then calls `created`. Each asset carries a `status`: `created` / `reused` / `placeholder` / `unavailable`. |
| ux-ui-designer | A state depending on a `placeholder`/`unavailable` asset is **not dev-ready**: it goes in `asset_gaps` and forces `dev_ready:false`. |
| PRD report | Lists any placeholder/unavailable assets and `asset_gaps` as **not dev-ready (placeholder art)**, and restates how to enable real generation. |

## Cost

`mcp-image` calls the Gemini image API and bills to your `GEMINI_API_KEY`. The
budget rules above (`balanced`/`1K`, ≤2 generations per request) keep spend low;
raise quality only when a request explicitly demands it.
